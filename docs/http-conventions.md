# HTTP response and request conventions (ENG-52)

New API controllers are thin transport adapters: parse input, obtain verified DM
scope, call actor-aware domain APIs and explicitly project the returned data.
They must not query Repo, reconstruct domain transitions, or serialize schemas,
changesets, snapshots/publications, worker errors or delivery guards directly.

## JSON envelopes

`ApiResponse.success(conn, projected_data, status: 200)` returns:

```json
{"data":{"id":"123","name":"Example"}}
```

Collections use `data: [...]`; an optional absent value uses `data: null`.
Pagination lives in `meta.pagination`. Successful creations normally use 201;
reads/updates use 200. A queued operation may use 202 only after its durable
transaction commits. Replay statuses must remain consistent with each endpoint's
creation contract; journal replay returns the same retained outcome.

IDs are decimal strings on new endpoints (including database IDs), UUIDs remain
strings, and UTC timestamps use ISO 8601. Versions, generations, counts and tick
numbers remain JSON integers. Use `ApiResponse.id/1` and `timestamp/1` explicitly.
Enums serialize as their string names. Existing quest import retains its 200
response and numeric IDs for compatibility; its payload is not silently changed.
Quest authoring's `definition` is also an existing content format, not resource
metadata: preserve its native integer clock references and opaque fields unchanged
for lossless read/save/release roundtrips. See [HTTP quests](http-quests.md).

Responses generated by the shared helpers set `Cache-Control: no-store`. The
success helper refuses structs even when nested. This is a backstop, **not** a
field whitelist: controllers still choose permitted fields and never pass whole
internal maps containing private metadata. JSON exception rendering also uses
the shared error envelope and never includes exception messages.

## Errors

`ApiResponse.domain_error/3` / `error/3` return:

```json
{"error":{"code":"stale_character"}}
```

| Status | Meaning / examples |
| --- | --- |
| 400 | `invalid_json`, `body_read_failed`, `bad_request` |
| 401 | Missing/invalid bearer credential; `unauthenticated`, with `WWW-Authenticate: Bearer` |
| 404 | Missing or forbidden resource/campaign; both use `not_found`. Missing applicable tick/draft/history may use `no_tick`, `no_draft`, etc. |
| 409 | State/concurrency conflict: `stale_*`, `active_tick`, `tick_locked`, `invalid_transition`, `idempotency_conflict`, `confirmation_required` |
| 413 | `payload_too_large` |
| 415 | `unsupported_media_type` |
| 422 | Invalid parameter/content: `invalid_parameters`, `invalid_flag`, `invalid_document`, etc. |
| 428 | A required concurrency token or idempotency key was omitted: `precondition_required` |
| 500 | Unknown/internal failure: `internal_error`, without internal reason/message/payload |

The mappings are a static allowlist, not arbitrary atom-to-string conversion.
An authenticated actor losing DM access is a concealed 404, not a renewed 401.
Framework method/permission failures may use 405 `method_not_allowed` / 403
`forbidden`; domain resource authorization still conceals forbidden resources.

For changesets, controllers pass allowed editable field names to
`domain_error(conn, changeset, fields)`. Details contain only field names and fixed
codes (`required`, `invalid_length`, `already_taken`, etc.), never rejected input,
constraint names, validation options or interpolated messages. Without a field
whitelist, no field details are exposed. Nested validation failures remain generic.
Controllers may explicitly pass already-projected public diagnostics; quest import
retains its existing `path`/`message` details. Never attach raw errors as details.

## Pagination

Keep existing domain pagination rather than inventing a global database query.

- **Page collections:** `page` defaults to 1; accept only positive decimal integers
  up to 100,000. Page size is fixed by the domain (published tick history: 20).
  `ApiParams.page_meta(page, page_size, more?)` produces pagination with `type:
  "page"`, `page`, `page_size`, `next_page` and `previous_page`; unavailable links
  are null. No expensive total-count query is required.
- **Keyset collections:** use one opaque `cursor` query parameter. Journal pages
  retain their frozen ceiling and next/previous boundaries. Encode validated
  domain cursors with `ApiTokens.cursor/3`, decode with `decode_cursor/3`. Tokens
  expire after 24 hours and bind campaign/configuration, actor and a resource
  label identifying the collection **and all filters**. A changed filter/subject
  must not reuse another collection's token. Missing cursor starts a new sequence;
  malformed/expired/misbound cursors return 422 `invalid_cursor`.

Cursor collection metadata uses `type: "cursor"`, the fixed `page_size`,
`next_cursor` and `previous_cursor` (null when absent). Do not expose cursor maps,
accept unsigned arbitrary offsets, or confuse HTTP cursors with Discord controls.

## Concurrency and idempotency

Mutation endpoints must require the relevant precondition; **never silently load
and submit the latest version on a caller's behalf**. Use `ApiParams.version/1`
and `uuid/1`; absent values return 428, malformed values return 422. Stale values
return the domain's 409 code. There are no blind retries after stale mutations.

- Character/flag edits carry `state_version`. Compare against the freshly loaded
  character, then pass that server-loaded record as `expected_character`; never
  reconstruct a client-supplied struct. The domain rechecks under its lock.
- Clock edits carry `snapshot_token`, issued by `ApiTokens.clock_snapshot/2`.
  Verify it against the freshly loaded clock, then pass the returned record as
  the domain's expected clock. The domain comparison still closes the race between
  HTTP verification and mutation. Tokens contain only IDs/scope and a record digest,
  not clock fields. They are signed, expire after 24 hours, and bind resource,
  campaign/configuration and actor.
- Quest working-copy writes carry `version`; review edits/publication carry
  `draft_id` (and existing input/die identities where required); delivery retries
  carry `generation`. Quest interventions must preserve their existing progression
  identity/version checks and pass a server-loaded `expected_progression`.
- Explicit confirmation remains a separate boolean (`true`), not implied by a
  valid version. In particular, ambiguous delivery retry must still call the domain
  with explicit `confirm_ambiguous: true`. Domain reasons and locks remain required.

For journal creation, require exactly one `Idempotency-Key` header, parsed by
`ApiParams.idempotency_key/1`. It accepts generic nonblank UTF-8 strings up to 200
bytes, without NUL. Do not substitute actor IDs, Discord snowflakes or a freshly
generated key on every retry. Journal domain scoping, fingerprint conflicts and
retained deleted outcomes are described in [journal creation](journal-creation.md).
Other endpoints only promise idempotency already supplied by their domains; the
header does not introduce a generic caching/replay service.

Tokens/preconditions never authorize access. Obtain scope from shared bearer auth
and still call the [actor-aware DM boundaries](dm-domain.md). No new functional
HTTP endpoints are added in this issue.
